Part II: Pipeline

Pipeline and configuration

A cascaded system: Telugu speech in, a Telugu text answer out, with a Whisper-family recognizer feeding an instruction-tuned LLM. Both models stay loaded and are reused across a whole evaluation.

FileRole

asr.pyASRWrapper: decodes audio with soundfile, averages to mono, optionally denoises, resamples to the model's rate, transcribes with a Hugging Face ASR pipeline. Timing is synchronized.
llm.pyLLMWrapper: applies the chat template (system + user), generates, returns only the newly generated text. Stateless: no history is kept between calls.
pipeline.pySpeechPipeline composes the two, rejects an empty transcript before calling the LLM, and exposes the JSON CLI.
denoise.pySpectral subtraction used by the ASR stage when enabled. See Denoising extension.

What is timed

  • asr_seconds: audio decoding, mono mix, optional denoising, resampling and transcription. Excludes model loading.
  • llm_seconds: prompt tokenization, generation and decoding. Excludes model loading.
  • total_seconds: wall clock around both stages, so it can exceed their sum slightly (pipeline overhead).
  • CUDA work is synchronized before each clock read. The first inference may include kernel initialization; the evaluator therefore runs --warmup 1 by default in the documented commands.

Model choices

StageUsedOriginal defaultWhy changed
ASRvasista22/whisper-telugu-smallopenai/whisper-large-v3Large-v3 plus a 7B LLM do not fit in about 6.5 GB free VRAM. The general openai/whisper-small was tried and rejected: see below.
LLMQwen/Qwen2.5-1.5B-InstructQwen/Qwen2.5-7B-InstructMemory (about 3 GB fp16 vs. about 15 GB).
Why not the general whisper-small Even with Telugu forced, openai/whisper-small transcribed this corpus's Telugu audio into Devanagari-looking text and looped on short clips. The first full clean run under it scored corpus WER 2.56 and CER 2.69, and was discarded. The Telugu-only fine-tune fixed it (WER 0.293). Full story in the decision log.
Why language: null The Telugu fine-tune ships a generation_config.json that predates transformers' language/task validation. Passing either to generate() raises ValueError: The generation config is outdated..., even for valid values (reproduced on transformers 5.15.0 and 4.57.6). ASRWrapper therefore treats a falsy language as "pass neither language nor task". Because the checkpoint is Telugu-only, nothing is lost. For a general multilingual Whisper checkpoint, set language: telugu and task defaults to transcribe.

The two config files

config_denoised.yaml is identical to config.yaml except for asr.denoise: true (and slightly shorter comments, with asr.revision: main noted as unpinned). It exists so the baseline-vs-improved ablation differs in exactly one setting.

These records are evaluation inputs, not scores. WER and response quality need reference labels, which is what the evaluator adds.

Built-in guards

  • An empty ASR transcript raises an error and the LLM is not called.
  • Audio must be finite and non-empty. Stereo is averaged to mono. Audio is resampled to the model's actual rate (scipy.signal.resample_poly), not just relabeled.
  • Over-long prompts and prompt-plus-budget overflow raise errors rather than truncating Telugu text or dropping chat-control tokens.
  • Each pipeline instance is intended for sequential use.
