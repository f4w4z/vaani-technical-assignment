Glossary and FAQ

Terms used across the docs, and fixes for the problems most likely to be hit.

Glossary

Evaluation terms

TermMeaning
WERWord error rate: word-level edits (insertions + deletions + substitutions) divided by reference words. A ratio, can exceed 1.
CERCharacter error rate: the same at the level of Unicode code points (whitespace removed).
RTFReal-time factor: processing seconds divided by audio seconds. Below 1 is faster than real time.
SNRSignal-to-noise ratio in dB. 0 dB means noise power equals signal power; 8 dB is cleaner.
Corpus rateA rate computed from summed edits over summed reference length, so long utterances weigh more than in a per-sample mean.
Word-overlap F1Lexical similarity between a reference and generated answer using multiset word overlap. A proxy, not semantic correctness.
Quality dropHuman-transcript answer quality minus ASR-transcript answer quality; positive means ASR errors hurt.
HallucinatedIn this project: an answer that does not state the reference fact and does not hedge or abstain. See the definition.
AbstainedA non-answer containing an uncertainty marker ("don't know", "sorry", "not clear").
Paired bootstrapResampling the same questions in two systems at once to get an interval for their difference.
95% CIThe 2.5th to 97.5th percentile of the bootstrap distribution. Containing 0 means not distinguishable from sampling noise.
AblationRemoving or switching off one component to measure its contribution.
CascadeA system built from separate stages (ASR, then LLM), as opposed to one end-to-end speech model.

Speech-model terms

TermMeaning
Speech LLMA language model that takes speech (and often produces speech) directly.
Full-duplexListening and speaking at the same time, with both streams modeled jointly.
Moshi / Mimi / HeliumThe full-duplex model, its causal neural audio codec, and its text LLM backbone.
Qwen2.5-Omni: Thinker / TalkerThe multimodal text LLM, and the speech-generating decoder fed by it.
Semantic vs. acoustic tokensTokens carrying linguistic content vs. those carrying voice and acoustic detail.
VQ / RVQVector quantization / residual vector quantization: discretizing audio features into codebook indices.
DiT, flow matchingA diffusion Transformer, and a generative method that transports noise to data along a learned path. Qwen2.5-Omni uses it to produce mel frames from speech codes.
BigVGANA neural vocoder turning mel-spectrograms into waveforms.
PAD / EPADMoshi's padding and end-of-padding tokens that time-align its own text with its audio.
Inner monologueMoshi predicting its own aligned text before the audio tokens, to improve linguistic quality.
Whisper / IndicWhisperOpenAI's ASR family / community fine-tunes of it for Indian languages.
TTSText-to-speech. Here, facebook/mms-tts-tel generates the evaluation audio.

Conversation terms (Part I)

TermMeaning
FloorWho currently "has the turn" in a conversation.
BackchannelA listener's short acknowledgment ("mm-hm") that does not take the floor.
Hesitation pauseA pause inside a speaker's own turn; the speaker is not finished.
Genuine interruptionThe user takes the floor while the assistant is speaking.
Continue / hold / yieldThe controller's three actions: keep talking, briefly pause output, or give up the floor and clear pending audio.
False yieldGiving up the floor when the assistant should have kept it.
Missed interruptionFailing to stop within the deadline after a genuine interruption.
Interruption-to-yield latencyTime from annotated interruption onset to actual playback stopping.

FAQ and troubleshooting

UnicodeEncodeError: 'charmap' codec can't encode characters

Windows consoles often use cp1252, which cannot print Telugu. Write results to a file, or run set PYTHONIOENCODING=utf-8 (PowerShell: $env:PYTHONIOENCODING = "utf-8") before running. The code itself writes UTF-8 JSON and CSV.

ValueError: The generation config is outdated...

You passed language or task to a checkpoint whose generation_config.json predates that API. Set asr.language: null for single-language fine-tunes. See Pipeline.

My ASR output is in the wrong script and WER is above 1

You are probably using a general multilingual checkpoint (such as openai/whisper-small) for Telugu. Use a Telugu-specific model, or a larger general one (whisper-large-v3) if memory allows. A WER above 1 is a signal to look at the raw transcripts.

CUDA out of memory

Both models stay loaded at once. Use smaller checkpoints (the defaults already are), set runtime.device: cpu (slow), or free GPU memory. Whisper-large-v3 plus Qwen2.5-7B-Instruct needs roughly 18 GB in fp16.

ModuleNotFoundError: No module named 'soundfile'

Dependencies are not installed in the active Python. Run python -m pip install -r requirements.txt and confirm python is the interpreter you installed into.

No module named 'tests.test_...'

The tests folder is not a package. Use python -m unittest discover -s tests -v, or add -p test_name.py for one file.

Warnings I can ignore

  • "unauthenticated requests to the HF Hub": set HF_TOKEN for higher rate limits; downloads still work without it.
  • "Using chunk_length_s is very experimental with seq2seq models": transformers' general caution about chunked Whisper decoding. The clips here are short, well under 30 s.
  • "torch_dtype is deprecated" and "Both max_new_tokens and max_length seem to have been set": library deprecation notices; max_new_tokens takes precedence.
  • "generation flags are not valid and may be ignored: temperature, top_p": sampling flags unused under greedy decoding.

git push fails with HTTP 408 or "Connection was reset"

That is the network path to GitHub, not a repository problem (reads still work). Try again on a steadier connection, and turn off any VPN or tunnel (such as Cloudflare WARP) that may be interfering with large uploads. Local commits are safe until the push succeeds.

Why are my numbers slightly different from the docs?

Fresh TTS synthesis is not seeded, so the audio differs. See what is deterministic.

Which PDF is the main report?

reports/report.pdf, the single paper. task1.pdf and task2.pdf are longer companions.

Does Part II test Part I's proposal?

No. Part II measures a cascaded pipeline, which has no floor-control decision. The proposal is specified but not run; see the proposal page.
